# Караоке

Сделано: текст песни, который идёт вместе с музыкой, у всех участников комнаты.

## Три способа дать тексту место

1. **`.lrc` вместе с песней.** При загрузке можно приложить файл с временными метками. Строки подсвечиваются по общей позиции трека, поэтому у всех они сменяются одновременно.
2. **Обычный текст.** `.txt` или вставка в окне «Текст песни». Показывается целиком, без подсветки.
3. **Текст внутри файла.** Воркер читает его из тегов MP3 и M4A (`USLT`, `©lyr`). Если текст в теге записан с метками `[мм:сс.хх]`, он тоже становится синхронным.

Текст из `.lrc`, вставленный вручную, приоритетнее встроенного.

## Как устроено

- Хранится в `tracks.lyrics` (JSON) и версионируется (`lyrics_version`), как обложка.
- `GET/PUT/DELETE /api/v1/rooms/{room}/tracks/{track}/lyrics`. Менять может тот, кто управляет плеером, и только у песен, загруженных в комнату.
- Разбор в `backend/app/services/lyrics.py`: `[offset:]`, несколько меток в строке, пословные метки `<мм:сс>` отбрасываются, до 600 строк и 20 000 символов. Текст попадает на страницу только как текст.
- Транскодер без сети возвращает тег с текстом в `result.json` (лимит результата поднят до 64 КБ).
- Текущая строка выбирается по общей позиции плеера, с опережением 150 мс. Прокрутка плавная, замирает на 4 секунды, если пользователь крутит сам, и отключается при `prefers-reduced-motion`. Ведущий может нажать на строку, чтобы перемотать.

## Чего нет

- Пословной подсветки. Формат `.lrc` с пословными метками разбирается, но слова внутри строки не подсвечиваются.
- Автоматической синхронизации текста с музыкой. Для своих файлов метки нужно принести.
- Демо-режима без сервера: там песен с текстом нет.
