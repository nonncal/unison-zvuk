# Синхронизация: что измерено и чего нет

## Измерено (reproducible)
`cd frontend && UNISON_E2E_ORIGIN=http://localhost:8080 UNISON_E2E_EXTERNAL=1 npm run test:e2e:api` — тест `timing.spec.ts`:
10 независимых браузерных контекстов с отдельными cookie на реальном backend/S3/worker, одна машина, 20 замеров.
Результат 16.10.2026: `p95 расхождения медиапозиций 22.1 мс, max 22.1 мс` (позиции `HTMLMediaElement.currentTime`; **не** акустика).
Отказ одиннадцатому участнику проверен в `api.spec.ts`/`social.spec.ts`.

## Что изменено в синхронизации (без «до/после» цифр)
- Коррекция дрейфа: порог входа 90 мс, выход 30 мс (гистерезис), скорость ±0.5–2% вместо ±1–3%, `preservesPitch=false`; жёсткий seek >400 мс как раньше. Покрыто юнит-тестом сходимости (`correction.test.ts`).
- Базовых «до» цифр по задержке команд и reconnect в этой сессии я **не снимал** — заявлять улучшение p95 нельзя.

## Не подтверждено (нужны устройства)
Внутренние цели проекта (p95 ≤150 мс desktop-desktop, ≤300 мс desktop/mobile) — только по протоколу:
1. Два устройства, одна комната, трек с щелчками/метрономом 120 BPM.
2. Микрофоном/второй камерой записать оба динамика одной дорожкой, 10 минут.
3. По разнице пиков щелчков посчитать p50/p95/max; отдельно — интервалы seek/buffering.
4. Повторить с Bluetooth-наушниками и мобильным клиентом; зафиксировать RTT/jitter.
Скрипт-заготовка телеметрии — `frontend/tests/timing.spec.ts`.
