# Unison: групповые комнаты и общий плеер

Реализация от 15 октября 2026. Этот документ уточняет первоначальный MVP и приоритетнее старых правил о двух участниках и свободном редактировании очереди. Стек клиента сохранён: React, TypeScript, Redux Toolkit/RTK Query, React Router, FSD. Сервер — Python/FastAPI.

## Как пользоваться

1. При создании выберите от 2 до 10 мест. Для существующей комнаты откройте «Настройки комнаты».
2. Включите «Зал ожидания», если гостей должен впускать ведущий. Гость отправляет заявку, ведущий нажимает «Впустить» или «Отклонить». Ожидание переживает обновление страницы.
3. Ведущий может выдать конкретному участнику права. Редактор получает общий плеер, очередь, загрузку аудио и замену обложки. Отзыв прав применяется сервером сразу.
4. В подборке можно выбрать текущий трек или добавить песню в очередь. В очереди доступны изменение порядка и удаление. Само редактирование списка не переключает звучащую песню.
5. Плеер поддерживает предыдущую/следующую песню, общую перемотку, перемешивание и три режима повтора. Кнопка повтора переключает: выключен → вся очередь → одна песня → выключен.
6. После конца трека сервер один раз выбирает следующий и задаёт общий старт через секунду. Если очередь завершилась при выключенном повторе, состояние — `ended`. Неисправные элементы пропускаются с сообщением.
7. У загруженного трека нажмите «Изменить обложку»: PNG, JPEG или WebP до 5 МиБ и 16 мегапикселей. Изображение нормализуется в WebP до 512×512; участники получают новую версию без перезагрузки. При отсутствии изображения показывается индивидуальная SVG-обложка. Извлечение картинки из ID3/APIC пока не реализовано.
8. Во время прослушивания доступны реакции ❤️ 🔥 👏 ✨ 🎶 😂 с именем автора. Они исчезают, поддерживают reduced motion и не меняют состояние плеера.
9. Стрелка рядом с названием открывает список ваших активных комнат и создание ещё одной. При переходе старые аудио и WebSocket освобождаются. Членство сохраняется, а отключение и смена ведущего подчиняются прежним таймаутам присутствия.
10. Ведущий может сменить приглашение, удалить участника или передать роль другому человеку с подтверждением.

## Права

| Действие | Слушатель | Редактор | Ведущий |
| --- | --- | --- | --- |
| Слушать, менять свою громкость, отправлять реакции | Да | Да | Да |
| Общий play/pause/seek, выбор/переход трека | Нет | Да | Да |
| Изменять очередь, загружать файл и обложку | Нет | Да | Да |
| Настройки, заявки, разрешения, приглашения, удаление и передача роли | Нет | Нет | Да |

Права хранятся на участнике (`canEdit`), по умолчанию выключены. UI скрывает/отключает управление, backend отдельно проверяет каждый HTTP/WS-запрос. Передача роли оставляет ровно одного ведущего. Конкурентные действия плеера сериализуются блокировкой комнаты и `expectedPlaybackRevision`; устаревший запрос получает conflict.

## Ограничения и поведение

- Вместимость включает активные участия и одобренные заявки с резервом места; гонка за последнее место не допускает переполнения. Обычный pending-гость место не занимает, не получает snapshot, список треков, аудиоссылки или WebSocket комнаты.
- До 50 ожидающих заявок на комнату; срок заявки — 15 минут. Допуск резервирует место до входа или истечения заявки. Отмена освобождает резерв; отклонённая сессия не может сразу создать такую же заявку повторно.
- Очередь до 100 уникальных готовых треков, хранится в PostgreSQL. Перемешивание проходит цикл без повторов; повтор всей очереди разрешает новый круг. «Назад» использует историю. Повтор одной песни применяется при автоматическом завершении; ручной «Вперёд» выбирает следующую.
- Автопереход использует секундное окно предзагрузки, без общей паузы из-за медленного клиента. Клиент после готовности догоняет серверную позицию. Это уточнение политики автоперехода; прежний критерий MVP о явном решении ведущего при неготовности остаётся для команды общего запуска.
- Следующая песня обычной очереди предзагружается после готовности текущей. Во время реальной буферизации клиент не выполняет повторные корректирующие seek. При ошибке источника — до двух повторных запросов URL с ограниченной задержкой; затем доступна ручная попытка.
- Лимиты аудио прежние: MP3/WAV/M4A, до 50 МиБ и 15 минут, нормализация в MP3 192 кбит/с, 44,1 кГц, стерео. FFmpeg остаётся в отдельном контейнере без сети.
- Ротация ссылки запрещает новые входы по старому токену; существующие участия сохраняются. Удаление запрещает API и новые медиассылки, закрывает сокет. Уже выданные ссылки действуют не более 5 минут; скачанные байты отозвать нельзя. Без аккаунтов удалённый пользователь может создать новую cookie-сессию и снова запросить вход; зал ожидания и смена ссылки помогают контролировать допуск.
- Реакции ограничены отдельно: 0,5/сек с кратковременным запасом 5. Они эфемерны и не входят в сохраняемую историю комнаты.
- Новые серверные функции доступны в основном API-режиме. Demo сохраняет прежний MVP для локальной проверки; серверные настройки/редактирование не эмулируются.

## Миграции и запуск

Новые ревизии `10ab15cd0001` и `10ab15cd0002` продолжают `8210be9ecf46`. Добавляют capacity 2…10, очередь, разрешения, заявки и обложки. Данные старых комнат сохраняются; каталог добавляется в их очередь.

```bash
# Из корня; .env содержит настройки вашей среды.
docker compose build api worker transcoder migrate
docker compose run --rm migrate
docker compose up -d api worker transcoder
```

При переходе с прежней версии нужен пересобранный API, worker и transcoder. Не удаляйте volumes. Откат первой миграции при наличии комнат вместимостью >2 запрещён, чтобы не обрезать данные.

## Исправление названий MP3

У части файлов BOM указывает UTF-16LE, а байты записаны как UTF-16BE: `挀甀琀 栀愀渀搀猀` вместо `cut hands`. Нормализатор распознаёт только целую последовательность однозначно переставленных печатных ASCII-символов. Корректные Unicode-теги сохраняются; произвольное «угадывание языка» не выполняется.

Новые загрузки исправляются автоматически. Для существующих треков есть команда с обязательным ID комнаты и сухим запуском по умолчанию:

```bash
cd backend
uv run python -m app.repair_metadata --room ROOM_UUID
uv run python -m app.repair_metadata --room ROOM_UUID --apply
```

Команда не меняет аудиофайлы; исправляет названия/исполнителей и публикует `track.updated`. В локальной комнате пользователя исправлены оба экземпляра `cut hands — Deftones`.

## Проверка и приёмка

Автотесты проверяют capacity 10 и конкурентное последнее место, доступ ожидающего гостя, одобрение/отклонение/истечение/отмену заявки, резерв места, отзыв редакторских прав, ротацию ссылки, удаление и передачу роли, сохранение очереди при повторном чтении БД, shuffle/repeat/автопереход и cover validation. Браузерные проверки используют независимые cookie-сессии и настоящий S3/worker: новый плеер, реакции, управление, смена комнат, собственный файл и обложка.

Адаптивность проверяется на desktop/tablet/mobile; основные новые элементы управления дополнительно проверяются при 390/768/1440 px. Unit-тесты покрывают готовность буфера, отсутствие повторных seek во время stall, общий отложенный старт и пример сломанного ID3.

Нагрузочная и акустическая приёмка десяти физических устройств, Safari/iOS/Android и измерение расхождения звука 150/300 мс остаются отдельными проверками. Реализация функций и браузерные тесты не означают автоматическое принятие этих NFR или закрытие всех историй в YouGile.
