# Unison — звучать вместе

Веб-приложение для совместного прослушивания музыки. Создай музыкальную комнату, выбери композицию или загрузи аудиофайл и пригласи друга по ссылке — вы будете слушать один трек синхронно.

Проект разрабатывается для кейса «Слушаем вместе»: ссылка на композицию превращается в совместный опыт, похожий на подключение к звонку.

## MVP

- Создание комнаты и генерация ссылки-приглашения.
- Вход по ссылке без обязательной регистрации.
- Выбор трека из подготовленной подборки или загрузка аудиофайла.
- Синхронные запуск, пауза и перемотка для двух участников.
- Отображение участников, готовности к прослушиванию и состояния подключения.
- Присоединение к текущей позиции трека и восстановление после потери связи.
- Индивидуальная громкость и выключение звука.

Ведущий управляет общим воспроизведением. Каждый участник получает один и тот же аудиофайл, а сервер через WebSocket передаёт состояние и время применения команд.

## Стек

| Часть | Технологии |
| --- | --- |
| Фронтенд | React, TypeScript, Redux Toolkit, WebSocket, React Router, Vite |
| Бэкенд | Python, FastAPI, Uvicorn, Pydantic |
| Данные | PostgreSQL, SQLAlchemy, Alembic |
| Аудиофайлы | S3-совместимое хранилище, FFmpeg в отдельном воркере |
| Инфраструктура | Docker Compose, HTTPS/WSS; Redis при масштабировании |

Бэкенд пишется на Python. Node.js используется только как инструмент сборки фронтенда.

## Развитие

После MVP: реакции, общая очередь треков и комнаты для компании. Голосовые и видеозвонки — отдельное возможное направление.

## Статус

Добавлены Python API, отдельный Celery worker, проверки здоровья, локальные сервисы
и миграции модели комнат и аудиофайлов с ограничениями PostgreSQL.
Работают создание комнаты, приглашение, вход, выход с передачей роли и закрытие.
WebSocket передаёт состояние, готовность и heartbeat. Сервер сохраняет команды общего
плеера с ревизиями, временем применения и повторяемыми подтверждениями.
Загрузка MP3/WAV/M4A проходит через подписанный PUT с проверкой размера, типа
и запретом перезаписи. Celery передаёт файл отдельному обработчику без сети:
он создаёт MP3 192 кбит/с, 44,1 кГц, stereo, доступный обоим участникам по одной версии.
Подборка содержит шесть оригинальных демонстрационных композиций с источниками
и лицензией CC0. Очистка удаляет незавершённые загрузки после часа, отменённые
и неудачные — после истечения права записи, файлы закрытой комнаты — через 24 часа.
Каталог и активное аудио сохраняются. Подключение экранов находится в разработке.
Прерванная обработка восстанавливается с ограничением до трёх попыток; запоздавший
результат старой попытки не меняет состояние. Неиспользуемые результаты обработки
удаляются после часа без удаления готового или обрабатываемого аудио.

## Локальный запуск

Требуются Docker Compose, Python 3.13, uv и Node.js 24 для фронтенда.
Локальные ключи генерируются в соседнем каталоге и не попадают в Git.

```bash
mkdir -p ../unison-runtime
chmod 700 ../unison-runtime
cd backend
uv sync --frozen
uv run python -m app.config --write-env ../../unison-runtime/local.env
cd ..
docker compose --env-file ../unison-runtime/local.env up --build -d
docker compose --env-file ../unison-runtime/local.env run --rm api uv run --no-sync python -m app.init_storage
docker compose --env-file ../unison-runtime/local.env run --rm worker /app/.venv/bin/python -m app.init_catalog
```

Повторно генерировать существующий `local.env` не нужно: команда защищена от перезаписи.
Инициализация каталога повторяема: готовые записи не создаются второй раз.
API доступен на `http://localhost:8000`, описание API — `/api/reference`.
`/health/live` проверяет процесс, `/health/ready` — PostgreSQL, Redis и приватный bucket.

Для разработки без контейнера API:

```bash
cd backend
UNISON_ENV_FILE=../../unison-runtime/local.env uv run uvicorn app.main:create_app --factory --workers 1 --no-access-log
```

В каталоге `frontend` выполните `npm install`, затем `npm run dev`.
Vite проксирует `/api`, `/ws` и `/health` на backend, сохраняя один origin для браузера.
Миграции выполняет сервис `migrate` перед запуском API.
В MVP API запускается одним процессом; PostgreSQL блокирует второго владельца комнат.
Worker обрабатывает отдельную очередь. После перезапуска общий плеер восстанавливается
в паузе с новой эпохой; ведущий может продолжить воспроизведение.

`transcoder` запускается без сети, с ограничениями CPU, памяти и временного хранилища.
Песочница открывает только исходник и выходной каталог текущей задачи. Worker и
обработчик обмениваются файлами через ограниченный общий том, доступ к Docker socket
не требуется. Отмена до `complete` доступна через DELETE загрузки; подписанное право
на запись истекает за десять минут, до этого резерв учитывается в общей квоте.
`S3_PUBLIC_ENDPOINT` задаёт адрес хранилища, доступный браузеру; `S3_ENDPOINT` — адрес
для внутренних обращений. CORS разрешает только `APP_ORIGIN`.

Перед изменяющими запросами клиент получает `/api/v1/bootstrap`: этот запрос создаёт
анонимную HttpOnly cookie-сессию и возвращает `csrfToken`. Затем отправляет точный
`Origin` приложения и `X-CSRF-Token`. Создание комнаты также требует UUID в
`Idempotency-Key`; повтор с тем же телом возвращает прежний результат.
Все JSON-поля на проводе используют camelCase; неизвестные поля отклоняются.
`snapshot.playbackRevision` задаёт ожидаемую ревизию для общего управления.

## Проверки Python

```bash
cd backend
uv run ruff check app tests migrations
uv run ruff format --check app tests migrations
uv run mypy app tests
uv run pytest
```

Интеграционные проверки создают и удаляют отдельные тестовые схемы в локальной базе,
не изменяя таблицы приложения. Для их запуска поднимите PostgreSQL и укажите файл настроек:

```bash
UNISON_ENV_FILE=../../unison-runtime/local.env uv run pytest
```

Для проверки полной цепочки загрузки в отдельном локальном Compose-окружении:

```bash
UNISON_ENV_FILE=../../unison-runtime/local.env UNISON_SYSTEM_URL=http://localhost:8000 uv run pytest tests/system/test_audio_pipeline.py
UNISON_TRANSCODER_CONTAINER=unison-local-transcoder-1 uv run pytest tests/system/test_transcoder_isolation.py
```

Первая проверка создаёт и закрывает тестовую комнату. Вторая проверяет файловую
и сетевую изоляцию, ограничения размера и времени внутри контейнера обработки.

## Контракты

Pydantic задаёт схемы HTTP и WebSocket версии 1. TypeScript-типы и проверки сообщений
генерируются из тех же схем; общие JSON-примеры проверяются обеими сторонами.
Время и позиции передаются целыми миллисекундами, ревизии ограничены точными целыми
JavaScript. Неизвестные поля, повторяющиеся ключи и нечисловые значения отвергаются.
При изменении моделей обновите схемы и типы:

```bash
cd backend
UNISON_ENV_FILE=../../unison-runtime/local.env uv run python -m app.contracts.export --output contracts
cd ../frontend
npm run contracts:generate
npm run contracts:check
npm run contracts:test
npm run build
npm run lint
```

Проверки сообщений работают без динамической компиляции кода в браузере.

## Диагностика

`/internal/metrics` отдаёт метрики Prometheus по отдельному ключу `METRICS_TOKEN`
в заголовке `Authorization: Bearer …`. При отсутствии ключа endpoint выключен.
Метрики показывают HTTP-задержки, подключения и ошибки WebSocket, очередь аудио,
heartbeat worker и возраст обработки. RTT и дрейф разделены по состояниям:
загрузка, буферизация и блокировка звука учитываются отдельно от стабильного playback.
Дневные счётчики и распределения хранятся в Redis 30 дней и переживают перезапуск API.
Правила оповещений для подключения к Prometheus находятся в `infra/monitoring/alerts.yml`.

Структурированные журналы приложения сохраняются в томе `logs-data`:
`api.jsonl` и `worker.jsonl`. Они содержат категории событий, случайный requestId
и тип исключения. Имена, аудио, заголовки запросов, аргументы и текст исключений
в журналы не записываются. Файлы ротируются по UTC, хранятся семь дней и ограничены
10 МиБ на день для каждого сервиса. `LOG_DIR` задаёт каталог при запуске без Docker.
Прочитать текущие события можно через `docker compose … exec api tail -f /logs/api.jsonl`.

## CI и нагрузка

GitHub Actions проверяет Python, типы, lint, сборку фронтенда и общие JSON-схемы.
Интеграционный этап поднимает свежий PostgreSQL, Redis, приватный S3 и обработчик,
проверяет миграции, гонки, outbox, WebSocket и реальные ошибки аудио. Все сервисы
и временные ключи принадлежат одному запуску и удаляются после него.

Для нагрузки используйте отдельный Compose-проект с `compose.load.yaml` и отдельным
файлом настроек. Профиль назначает случайные localhost-порты, собственные тома,
2 CPU и 2 ГиБ для API. Повышенные лимиты создания действуют только в этом профиле;
обычные проверки ролей и квоты аудио сохраняются. После инициализации хранилища
обновите `S3_PUBLIC_ENDPOINT` по фактическому порту storage и подготовьте каталог.
Адрес API можно получить через `docker compose … port api 8000`.

```bash
cd backend
uv run python -m benchmarks.load --base-url http://localhost:PORT --rooms 100 --seconds 1800 --project unison-load --report ../../unison-runtime/load/result.json
```

Сценарий открывает 200 отдельных WebSocket, выполняет clock probes, heartbeat,
play/pause/seek и запросы состояния, параллельно загружает два файла.
Отчёт содержит задержки HTTP/WS, ошибки, завершение загрузок и CPU/RAM контейнеров.
Созданные комнаты и подключения закрываются в конце. Результаты сохраняйте
вне репозитория. Нагрузочный сценарий измеряет сервер и транспорт; слышимую
синхронизацию проверяйте отдельно на независимых устройствах.
