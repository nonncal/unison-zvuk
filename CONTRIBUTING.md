# Работа с проектом

## Коммиты

Формат Conventional Commits: `type(scope): краткое описание`.

- `feat` — новая пользовательская возможность;
- `fix` — исправление ошибки;
- `perf` — улучшение производительности;
- `refactor` — изменение структуры без смены поведения;
- `test` — тесты и тестовая инфраструктура;
- `docs` — документация;
- `ci` — автоматические проверки;
- `chore` — обслуживание инструментов и зависимостей.

Один коммит решает одну понятную задачу. Примеры:

```text
feat(room): add invitation form
fix(audio): report updated buffer readiness
refactor(frontend): isolate FSD slices
test(frontend): cover independent browser sessions
```

Не собирайте спецификацию, приложение и тесты в один общий коммит. Добавляйте в индекс конкретные файлы или hunks, проверяйте `git diff --cached`. Не переписывайте опубликованную историю ради изменения оформления коммитов.

## Frontend

Архитектура FSD: `app → pages → widgets → features → entities → shared`. Импорты между слайсами только вниз, через публичные `index.ts`. Связь сущностей через `@x` должна быть явно адресована потребителю. Проверка `npm run architecture:check` входит в CI.

После изменения логики запустите lint, проверку архитектуры, относящиеся к изменению тесты и сборку. После изменения API обновите схемы Python и сгенерируйте TypeScript; проверьте общие fixtures. Для интеграции используйте настоящий локальный backend и `npm run test:e2e:api`.

Не коммитьте `.env`, runtime-ключи, cookies, invite-токены, локальные БД, traces и файлы операционной системы. API использует Python; Node.js — инструмент фронтенда.
